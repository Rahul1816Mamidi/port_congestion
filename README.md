# Port Congestion Risk Estimator

For a vessel arriving at a port, this estimates the **probability of congestion** (wait for a berth > 12 h), a **confidence score**, and the **key factors** behind the prediction with suggested operational actions. It runs locally in seconds, with **no external APIs or API keys**, on a synthetic 450-call dataset generated by a port queueing simulation.

Technical report (PDF, 3 pages): [`report/technical_report.pdf`](report/technical_report.pdf). Module-level details: [`technical.md`](technical.md).

> **Honest scope note:** the data is synthetic (no real AIS data is used). Scores show the pipeline works end to end, not real-world accuracy. See the limitations section of the report.

## Quick start for reviewers: interactive tester
The trained model is included, so no training is needed:
```bash
python -m pip install -r requirements.txt
streamlit run app.py
```
Your browser opens a page where you enter a port, traffic, weather and arrival time (or pick a preset, or load a held-out call to compare with its actual outcome) and get the probability, confidence, factor chart and suggested actions. You can also tick "unknown" for the queue, 7-day history or weather to see how missing data is handled. If the saved model cannot be read (for example after a library upgrade), the app retrains itself from the included dataset in about a minute.

## Prerequisites
- Python **3.11 or newer** (developed and tested on 3.12.3). Dependencies are pinned in `requirements.txt`.
- About 500 MB free disk for packages. No GPU needed (tabular data, CPU only).

## Setup
```bash
python -m venv .venv
# macOS/Linux:   source .venv/bin/activate
# Windows (PowerShell):   .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

## Run (in order)
```bash
python -m src.generate_data     # data/port_calls.csv  (450 calls, 5 ports)
python -m src.train             # outputs/model.joblib
python -m src.evaluate          # outputs/metrics.json + 4 figures
python -m src.seed_check        # optional: stability across 5 seeds (~1 min)
python report/build_report.py   # report/technical_report.pdf
python -m pytest -q             # tests (13)
```
With `make` installed: `make all` (data, train, evaluate, report), `make test`, `make demo`.

## Try a prediction
```bash
python -m src.predict --scenario calm       --port PORT_C
python -m src.predict --scenario storm-peak --port PORT_C
python -m src.predict --port PORT_B --queue 6 --arrivals-24h 9 --wind 28 --wave 3 --storm --arrival "2026-10-14 06:00"
python -m src.predict --call-id C0420       # a call from the dataset; also prints the actual outcome
python -m src.predict --scenario busy --json
python -m src.predict --help
```
Example (`--scenario storm-peak --port PORT_C`):

## Configuration (environment variables, all optional)
| Variable | Default | Meaning |
|---|---|---|
| `PC_SEED` | 42 | Random seed for data generation and models |
| `PC_N_RECORDS` | 450 | Number of synthetic calls (100-500 recommended) |
| `PC_THRESHOLD_H` | 12 | Congestion definition: wait (hours) above which a call is congested |
| `PC_THRESHOLD_BETA` | 1.0 | F-beta used to pick the alert threshold (>1 favours recall) |
| `PC_DATA_PATH` | `data/port_calls.csv` | Dataset location |
| `PC_MODEL_PATH` | `outputs/model.joblib` | Trained model location |

Changing `PC_THRESHOLD_H` or `PC_SEED` requires re-running generate, train and evaluate.

## Structure
- `src/generate_data.py` queueing-simulation data generator (ground truth and noise)
- `src/features.py` feature matrix, factor groups, chronological split
- `src/modeling.py` models, calibration, bootstrap confidence ensemble
- `src/train.py`, `src/evaluate.py`, `src/seed_check.py` training, evaluation, stability check
- `src/explain.py` SHAP factors, sentences, suggested actions
- `src/predict.py` command-line predictor
- `app.py` Streamlit interactive tester (same model and explanation code)
- `tests/` 13 tests on the generator, split, SHAP additivity, predictions, CLI and the web app
- `report/` report builder and the PDF; `outputs/` metrics and figures; `data/` generated CSV

## Common errors
| Problem | Fix |
|---|---|
| `No trained model at ...` | Run `python -m src.train` first |
| `ModuleNotFoundError: src` | Run commands from the repository root with `python -m src.<module>` |
| Install fails on numpy/pandas | You need Python 3.11+ (`python --version`) |
| `make: command not found` (Windows) | Use the plain `python -m ...` commands above |
| App port already in use | `streamlit run app.py --server.port 8502` |
| Loading the model fails after changing library versions | Re-run `python -m src.train` (the model file is a pickle tied to library versions) |

## Using real AIS data later
The pipeline consumes a table with the columns listed in `technical.md`. Real AIS (for example NOAA Marine Cadastre) would need port polygons and anchorage dwell detection to build `queue_length`, `wait_hours` and `congested`, plus an external weather source. That step is not implemented here.
